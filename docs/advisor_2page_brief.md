## 页 1｜AutoBrep 核心：把 B-Rep 变成「会写句子的 CAD」

### 一句话定位

AutoBrep 不输出网格，而是用 **GPT 式自回归** 直接写一条离散 token 序列；序列里同时编码 **几何** 和 **拓扑**；再解码成面/边点阵，用 OCC 缝成 STEP。

### 主图（页心，建议手绘/PPT 一图打尽）

```text
[复杂度 prompt 5 token]
        ↓  自回归抽样 (top-p + temperature)
[CAD token 序列：按面邻接图 BFS 逐面写]
        ↓  解析
[面/边 bbox] + [面/边 FSQ 形状码] + [Face ID 引用 = 邻接]
        ↓  FSQ 解码 + 联合优化 + Sewing
              STEP 实体
```

### 必须讲清的 4 个点（各 1–2 句）

**① 词表里没有「立方体/孔」**  
只有：控制符、Face ID、bbox 量化 bin、面/边 FSQ 码本（默认约 3k 词）。形状类型藏在 FSQ 码里，不是语义标签。

**② Face ID 学的是「指针」，不是外观**  
声明：`BOF + id=k + bbox + 面FSQ`  
引用：`prev=k + 边bbox + 边FSQ` → 表示「当前面与已生成面 k 共边」。拓扑靠引用表达。

**③ 无条件输入极弱**  
推理固定前缀：`BOS BOM GEN_* EOM BOC`（复杂度 easy/mid/hard）。  
**不能**指定「带通孔立方体」；同 prompt 结果不同，是因为后续 token 在分布上随机抽，不是 prompt embedding 随机。

**④ 两阶段几何**  
冻结的 Surface/Edge FSQ-VAE：UV 点阵 ↔ 离散码。AR 只预测码 + bbox + 拓扑引用；重建阶段再变连续几何并缝合（会失败 → 有 debug 中间结果、无 STEP）。

### 页 1 收束句（过渡到页 2）

> 因此：无条件 = 从先验采样 CAD「句子」。若要可控，必须在句子前面（或旁边）加 **条件信息**，并训练模型读它。

## 页 2｜条件生成：缺口 → 我们现状 → 路线与难易

### 主图（条件怎么接）

```text
现状（已跑通）：     [复杂度] → AR(冻结权重可做 infer) → STEP

目标（点云条件）：   [点云编码器] → 条件前缀/cross-attn → AR(建议冻 FSQ+尽量冻 AR) → STEP
                         ↑
              数据：点云 ↔ AutoBrep token（可由 STEP/mesh 现采点云）
```

### 我们实现了什么（如实、短）

| 已完成 | 说明 |
|--------|------|
| 预训练权重落地 | `ar` + `surf-fsq` + `edge-fsq` |
| 无条件 infer | exp_launcher 接入：`run.sh infer`、前端可调 complexity / temperature / top_p 等 |
| 工程理解 | 词表结构、BFS 序列、debug≠失败、失败在 OCC 重建 |

| 未完成 | 说明 |
|--------|------|
| 点云条件训练/推理 | 词表有 `BOPC/EOPC` 占位，代码 TODO，未接 |
| 正式 ABC 训练数据 | 需 ABC-1M parquet / 同格式 processed（本地有 ABC STEP/OBJ，未做成 AutoBrep 格式） |
| 条件版 train mode | launcher 目前以 infer 为主 |

### 若要做条件生成，技术上要补什么

1. **数据**：`点云 ↔ B-Rep token`（不是只存「点云–STEP」就完事；STEP 还要预处理成与 AutoBrep 相同的 token/UV 格式）。点云可从 GT solid **确定性采样**。  
2. **模型**：点云编码器 + 接入方式（离散前缀 / cross-attn）；**FSQ 必冻**；AR 可先冻再 adapter，或小学习率微调。  
3. **训练**：条件 dropout（部分步仍无条件）→ 同一模型可无条件/有条件。  
4. **推理**：infer 读入点云文件，写出 STEP + 对齐指标（Chamfer 等）。

### 想实现什么 vs 花时间能做 / 难做

| 目标 | 难度 | 原因 |
|------|------|------|
| 点云 → 条件 → 出 STEP（冻结 FSQ + 轻量适配） | **能做**（数周级，视数据与算力） | 管线清晰；难点在数据做成 token 对齐 + 接好条件模块 |
| 用现有无条件权重「零训练」直接点云控制 | **难/不现实** | 权重没见过点云；仅改 prompt 不够 |
| 指定「通孔立方体」这类语义文本控制 | **难** | 词表无语义零件类；需新条件或检索式控制 |
| 稳定高成功率 watertight + 复杂孔特征 | **中难** | 重建失败本就存在；条件更准可减轻，但 OCC 缝合仍是瓶颈 |
| 图像/三视图条件 | **能做但更重** | 需渲染对或现有多视图数据；编码器与数据协议另开一线 |
| 部分 B-Rep 补全（论文已有统一框架） | **相对容易（比点云）** | `BOGEOM` 路径代码半成品，可作条件生成的热身 |

### 建议向导师承诺的近期路径（务实）

**Phase A（热身，可选 1–2 周）**：打通/验证部分面条件（`BOGEOM`），证明「条件前缀 + 冻 FSQ」可行。  
**Phase B（主线）**：ABC token 数据 + 点云现采 → 冻 FSQ（+ 策略性冻 AR）→ 只训点云条件头 → launcher `train/infer`。  
**不承诺短期**：纯文本语义指定零件；零样本点云控制。

### 页 2 收束句

> 无条件我们已经能采样；条件生成的本质是 **补条件通道与对齐数据**，不是重训整个几何码本。优先冻结 FSQ，把算力花在「点云怎么进 AR」和「数据 pair 是否干净」。

## 汇报时口头备用（被追问）

- **Q：同 prompt 为何不同？** A：后续 token multinomial 抽样，不是 Face ID embedding 随机。  
- **Q：通孔在 token 哪？** A：圆柱面 FSQ + 与顶/底共圆边的引用，无 HOLE 词。  
- **Q：为何不直接点云–STEP？** A：AR 吃的是 token；STEP 要先变成与训练一致的序列，否则对不齐损失。  
- **Q：最大风险？** A：① 缺正式 processed 数据；② 重建失败率；③ 冻太死导致条件吸不上、全开又易毁先验。
