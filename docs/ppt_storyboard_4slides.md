# AutoBrep 汇报 PPT 分镜说明（交给做图 AI 用）

> 共 **4 页**。风格：学术汇报、干净、偏工程示意；**不要**紫粉霓虹、不要玻璃拟态、不要大段英文堆砌。  
> 主色建议：深蓝灰 `#1F2A37` + 青灰强调 `#2A6F7A` + 浅底 `#F4F6F8`；失败/难用暖橙 `#C45C26`；已完成用松绿 `#2F6B4F`。  
> 字体：中文标题用思源/黑体类，英文专有名词保留 AutoBrep / FSQ / STEP / B-Rep。

---

## 第 1 页｜核心技术（上）：它在写什么样的「CAD 句子」

### 本页目标（听众 30 秒应记住）
AutoBrep 不是画网格，而是像写句子一样，**一个 token 一个 token 吐出 B-Rep**；句子里同时有形状和「谁挨着谁」。

### 版式
- **顶部**：大标题一行 + 副标题一行  
- **中部 60%**：横向流程图（主视觉）  
- **底部 25%**：三个小卡片（词表三类信息）  
- **右下角极小字**：无条件输入示意

### 标题文案
- 标题：`AutoBrep：用自回归「写」出 B-Rep`
- 副标题：`把 CAD 实体变成一条离散 token 序列，再解码缝合成 STEP`

### 主图（请画成从左到右的流水线，带箭头）

**节点 1｜弱提示**  
画一个小胶囊/聊天泡：  
`BOS  BOM  中等复杂度  EOM  BOC`  
旁注小字：`无条件：几乎不指定长什么样`

**箭头** 标注：`top-p + 温度抽样（每一步随机选下一个词）`

**节点 2｜CAD 句子（本页重点，画成「书页/磁带」纵向展开）**  
把序列画成一层层「楼层」：

```
第0层 BOL … 先写出第1个面（只有框+形状码，还没有边）
第1层 BOL … 写出邻居面；每来一个新面，就「指回」旧面并吐出共享边
第2层 … 继续向外扩张（像 BFS 逛房间）
… EOC  EOS
```

视觉隐喻：**迷宫里按广度优先推门**——先站在一个面，再推开相邻面，边是两扇门之间的门框。

**箭头**

**节点 3｜落地**  
三个小图标连到一起：  
`bbox 盒子` + `FSQ 形状码` + `Face ID 箭头引用` → `缝合` → `STEP 零件图标`

### 底部三卡片（等宽）

**卡片 A｜位姿**  
图标：线框包围盒  
标题：`Bounding Box`  
正文：`面/边在空间里的位置与大小（量化成离散 bin）`

**卡片 B｜形状**  
图标：弯曲网格 / UV 格子  
标题：`FSQ 形状码`  
正文：`平面、柱面等外观藏在码本里，不是文字标签「圆柱」`

**卡片 C｜拓扑**  
图标：两个面之间一条边 + 回指箭头  
标题：`Face ID 引用`  
正文：`说「连到之前的面 k」——像代词，不负责长什么样`

### 页脚一句（过渡）
`下一页：这条句子具体怎么吐字，以及为什么同提示也能长出不同零件。`

### 给做图 AI 的额外约束
- 不要出现「立方体/孔」作为输入框内容（强调输入很弱）  
- 主图避免超过 6 个框，保持可读  
- 「BFS 逛房间」可用简化平面图小插画放在节点 2 旁

## 第 2 页｜核心技术（下）：吐字规则 + 为何同 prompt 结果不同

### 本页目标
讲清 **一个面怎么写进句子**，以及 **随机性来自续写抽样，不是 prompt 在抖**。

### 版式
- **左 55%**：一个「面的书写模板」大示意图（语法树/乐高说明书风格）  
- **右 45%**：上半「通孔立方体」示意（拓扑故事）；下半「同 prompt 不同结果」对比

### 标题文案
- 标题：`句子怎么写：面 = 声明；边 = 指回旧面`
- 副标题：`词表里没有「孔」「圆柱」——孔是结构关系长出来的`

### 左侧大图：单个面的 token 模板（务必形象）

画成一张「装配说明书」竖条：

```
┌ BOF 开始一个面
│  Face ID = 给这个面起名（如面#3）
│  六个数字：这个面的包围盒
│  四个 FSQ 码：这个面的形状（平的/弯的…）
│  ┌ 若已有更早的面：
│  │  指回「面#1」+ 边的包围盒 + 两个边 FSQ 码
│  │  指回「面#2」+ …
│  └ （每指回一次 = 声明一条共享边）
└ EOF 这个面写完
```

旁注气泡：  
`Face ID embedding 学的是「可引用的名字/指针」，不是外观。`

### 右侧上：通孔立方体（讲故事，不要公式）

画一个剖开的方块 + 中间竖孔：

1. 先写出底面（带圆洞倾向的形状码）  
2. 再写四个侧面 + 孔壁（孔壁的 FSQ 更像弯柱面）  
3. 最后写顶面：既指回侧面（外框直边），又指回孔壁（圆边）  

小标题：`「通孔」≈ 顶/底通过圆边接到同一柱面`  
红叉标注：`没有 HOLE 这个词`

### 右侧下：同 prompt、不同零件

左右两个零件剪影（都从同一胶囊 prompt 出发），中间分支箭头标注：

`第 6、7、8… 个 token 每次从概率分布里抽到的不同 → 分叉`

小字三条：
- `temperature=0`：近似每次一样（贪心）  
- `默认 temperature>0`：故意多样化  
- `复杂度标签`：只是粗档位，不是零件类型

### 页脚
`以上是无条件生成的全部核心。下面两页：我们做到哪、还想做啥、什么容易什么难。`

## 第 3 页｜已经做了什么 / 想做什么

### 本页目标
诚实对照：工程上无条件已通；研究上条件生成是下一步。

### 版式
- **左右分栏**（已做 | 想做），中间一条时间箭头「下一步」  
- 或上下：「现状底座」大条 + 「目标形态」大条  
推荐 **左右分栏 + 底部一条「缺口」横幅**

### 标题
`现状与目标：从「能采样」到「能按点云生成」`

### 左栏｜已经做了（绿色勾）

标题条：`已完成（可演示）`

列表（每条配小图标）：
1. **预训练权重就位**：AR 主模型 + 面/边 FSQ  
2. **无条件推理跑通**：输入复杂度等，输出 STEP  
3. **实验编排接入**：exp_launcher 可启动 infer、调采样参数  
4. **机制摸清**：词表结构、BFS 写法、Face ID=指针、debug 是中间结果不是失败文件夹

右下小窗「演示输入」：  
再画一次那 5 个 token 胶囊，标注 `唯一可控：复杂度档位`

### 右栏｜想做（青色空心箭头）

标题条：`目标（点云条件生成）`

画目标流水线（比第 1 页多一块「点云」）：

```
点云 → 点云编码器 → 条件信息（前缀或 cross-attn）
                         ↓
              AutoBrep AR（尽量冻结已有权重）
                         ↓
                       STEP
```

三条目标陈述：
1. **冻结 FSQ（必做）**：几何码本不动，省算力、保重建先验  
2. **条件模块可训**：点云怎么进入「写句子」的上下文  
3. **数据对齐**：点云 ↔ AutoBrep 的 token/UV 格式（不是只存裸 STEP）

### 底部横幅｜当前最大缺口（橙色浅底）

文案：  
`缺口不在「会不会抽样」，而在：① 条件通道未接好；② 缺与 AutoBrep 对齐的 processed 数据（点云可从实体采样，但目标侧要是 token 级监督）。`

### 视觉细节
- 左栏用实心绿勾，右栏用虚线框表示「规划中」  
- 不要写太多路径名/文件名（导师不关心绝对路径）

## 第 4 页｜能做 / 难做（投入产出）

### 本页目标
帮导师判断：近期押什么、别押什么。

### 版式
- **2×2 矩阵** 或 **双列「能做 | 难做」+ 底部「建议路线」**  
推荐：**左列能做、右列难做**，底部一条三阶段路线。

### 标题
`可行性：花时间能推进的 vs 短期不宜承诺的`

### 左列｜花时间能做到（松绿色）

每条 = 「目标」+「为何可行」小字：

1. **点云条件生成（冻结 FSQ + 轻量适配头）**  
   小字：主路径清晰；工作量在数据协议与条件接入，不在重做几何码本  

2. **从本地 CAD 实体现采点云，做成可复现 pair**  
   小字：不必等「天然扫描点云」；关键是与 token 对齐  

3. **部分 B-Rep 补全作热身（论文框架已有）**  
   小字：比点云更贴近现有序列设计，可验证「条件前缀」是否训得动  

4. **Launcher 上补 train/infer 条件参数**  
   小字：工程项，可控  

### 右列｜难做到 / 别早承诺（暖橙）

1. **不训练、只改 prompt，就用现权重做点云控制**  
   小字：模型从未见过点云条件  

2. **文本点名「要一个带通孔的正方体」**  
   小字：词表无零件语义；属另一类控制系统  

3. **复杂特征 + 近 100% 水密成功**  
   小字：无条件时重建失败已存在；条件能改善，但 OCC 缝合仍是硬瓶颈  

4. **图像/三视图条件与点云同一周交付**  
   小字：可行但是另一条数据与编码器战线，别和点云主线并行承诺  

### 底部｜建议路线（深色条，三步）

画成三块里程碑：

`Phase A 热身：部分面条件 / 通条件前缀`  
→ `Phase B 主线：点云编码器 + 冻 FSQ 训练 + 指标（如 Chamfer）`  
→ `Phase C 可选：图像条件 / 更强可控`

旁注一句：  
`汇报口径：先保证「条件进得去、损失降得下、能出 STEP」；再谈语义级可控与极致成功率。`

### 结束页不需要；第 4 页右下可放一句感谢/讨论

`请导师拍板：主线是否定为「点云→B-Rep（冻 FSQ）」；热身是否做部分面条件。`

## 给做 PPT 的 AI：全局检查清单

- [ ] 4 页结构固定：核心上、核心下、已做/想做、能做/难做  
- [ ] 第 1–2 页出现且只强调一次完整 prompt：`BOS BOM 复杂度 EOM BOC`  
- [ ] Face ID = 指针；FSQ = 形状；bbox = 位姿——三页内符号一致（同色同图标）  
- [ ] 第 3 页「已做」不要夸大成「已完成点云条件」  
- [ ] 第 4 页「难做」语气坚定但不负面攻击现有工作  
- [ ] 每页字数克制：标题短、bullet ≤ 5、大图说话  
- [ ] 不要把代码路径、conda、端口写进幻灯片正文
